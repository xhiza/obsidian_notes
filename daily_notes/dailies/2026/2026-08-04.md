## Notes
- Backoffice / start-stop behavior:
  - Databases in maintenance should not be started or stopped from backoffice; maintenance means investigation is in progress, and changing state there can break process or trigger alerts.
  - Operators should not start a DB through backoffice when there are no credits; for L3/debugging, Support should start from inside `n10` and follow a clear playbook.
  - Leila planned to adjust her PR so billing is not skipped.
- Update distribution flow:
  - Leila confirmed the UI update button is driven by DynamoDB `versions` plus distribution-table data; if the minimum version in the distribution table is above the current DB version, the Update button becomes available.
  - `SPOT-23949` remains the historical reference for the distribution-table component and stream GitHubCI workflow.
  - `Update Now` appears to create scheduling through the step function path, with a UTC/local-time mismatch causing the observed delay.
- Blacklist / hard-disable path:
  - The practical path for blacklisting DBs from automated update visibility is to set `AUTOMATED_UPDATES_HARD_DISABLED = true` in the management/SaaS database settings.
  - Andrew asked for DB names/email domains and clarified that some old systems may be expected, deleted, or still tied to migration state.
- Staging / cost:
  - `#engineering-cloud-cost-alerts`: SaaS staging customer account spend was above the normal budget, around `350` versus the usual `150`; e2e tests and India test runs were likely contributors.
  - Need cleanup/attribution around staging spend and the India-region upgrade restriction.
- Prod delete / MCP alerts:

  - Edis noted that the new C4 is needed in prod ASAP, especially because deletion has mutex-related handling.
