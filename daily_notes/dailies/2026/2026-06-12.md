SIP meeting with AWS TAM team

Virtual Schemas / UDF / AppArmor issue in production SaaS DBs
The main topic today was an investigation into Virtual Schemas stopping in a production database. You found, with Aleksandr’s help, that the root cause was AppArmor being enabled. Since AppArmor is enabled by default on Ubuntu 24.04 and most production customer DB nodes are now on 24.04, you raised the risk for customer databases still running older Exasol versions.  

Version and fix clarification
The thread clarified that the relevant fix should be available starting with @exasol-2025.1.5, also included in 2025.2.0. Pablo noted the AppArmor-disabled-on-update change was part of 2025.1.5 and 2025.2.0, while Aleksandr clarified the issue he had seen was on 2025.1.4.  

Workaround discussion for affected systems
You asked what the next step should be if customers complain, since 8.29.x cannot be upgraded directly to the latest version. You proposed the ad hoc workaround:

```
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```


Aleksandr noted that this is reverted on restart, and Benedikt confirmed the command should work but would need to be persisted via a sysctl file or otherwise applied on startup/new nodes. Andrew suggested applying the command, or disabling AppArmor, across SaaS systems updated to 25.1 for now.  

SaaS e2e / UDF test validation
Andrew raised that SaaS e2e tests should catch “all UDFs broken in SaaS” and asked whether the relevant test is still running. You triggered a UDF-only e2e test and said you would share the results.  

Service Desk admin request
